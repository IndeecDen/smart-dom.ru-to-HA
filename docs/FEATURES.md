# Что покрыто и что требует проверки

Перечень сопоставлен с локальным APK `com.ertelecom.smarthome` 9.10.0,
versionCode 91000020. [Каталог API](apk-api-9.10.0.json) содержит **112
деклараций Retrofit**; это число запросов, а не 112 пользовательских функций.
Наличие endpoint в APK само по себе не доказывает доступность в вашем тарифе.
SHA-256 исходного APKM: `1ebdfe5fdb68f19e07d9753cb2f4d2e4ee2456ab9c3cd9d81149ac8430577929`.
Он использован только для анализа и в поставку не входит.

| Функция приложения | Реализация в HA | Уровень подтверждения |
|---|---|---|
| Вход по телефону/договору, SMS или паролю | UI config flow и повторный вход | Кодовая основа и unit; реальный аккаунт не проверен |
| Домофон, калитка, дверь/шлагбаум | Сущности `lock`, команда открыть | Кодовая основа и unit; физический отклик не проверен |
| Личные и общие камеры, снимок | Сущности `camera`, HLS/go2rtc | Кодовая основа и unit; поток не проверен на аккаунте |
| Архив камер | Media Source и карточка событий | Кодовая основа и unit; срок хранения задаёт оператор |
| Звонок и разговор | FCM-событие, SIP, карточка микрофона | Идентификаторы FCM сверены с APK; живой вызов не проверен |
| История звонков и движение | `event`, история и автоматика | Кодовая основа и unit |
| Баланс и блокировка | `sensor`, `binary_sensor`, действие финансов | Кодовая основа и unit |
| «Не беспокоить» | `switch` | Кодовая основа и unit |
| Временные пропуска | Список, разрешённые двери и сроки, создать/удалить | Endpoint и JSON-поля сверены с APK; живой вызов не проверен |
| Электронные ключи | Список, добавить/удалить/активировать/переименовать, уведомления | Endpoint и JSON-поля сверены с APK; живой вызов не проверен |
| Событие «открыт ключом» | Тип `key_activated` на сущности истории, realtime-пуш FCM и опрос истории, локальные имена ключей | Тип события, ключ пуша `u` и поля payload сверены с APK; **живого `accessKeyActivated` не наблюдали** — текст оператора и тип источника не проверены на аккаунте |
| Настройки личных камер | Запись, движение, громкость, зеркало, PTZ, имя | Endpoint и диапазоны сверены с APK; модель камеры может не поддерживать |
| Документы и обращения | Список, отметить прочитанным, создать обращение | Endpoint и JSON-поля сверены с APK; живой вызов не проверен |
| Оплата, банковские карты, СБП | Просмотр финансов; операция оплаты остаётся в официальном приложении | Нужны платёжные переходы и live-проверка |
| Подключение новой камеры по Wi-Fi, поиск в Bluetooth | Официальное приложение на телефоне | Требует мобильных радио-интерфейсов и разрешений Android |
| Гостевая авторизация QR, договоры, лицо/биометрия | Официальное приложение | Контракты и безопасность в HA не подтверждены |
| Параметры зон движения, тарифы, магазин услуг, чат поддержки | Официальное приложение | APK содержит вызовы; безопасная схема управления не подтверждена |

Верхние блоки образуют рабочую **первую beta**, а не обещание полного повторения
мобильного приложения. Реальная функциональность зависит от модели устройства,
адреса, тарифа и изменений закрытого облачного API. Для функций из последних
строк нужен отдельный входной сценарий или реальная тестовая среда; не стоит
угадывать платёжные и гостевые контракты по одному APK.

## Ограничения определения ключа

Оператор не отдаёт идентификатор ключа ни в одном представлении события — REST,
FCM и WebSocket содержат только `eventTypeName`, `timestamp` и подготовленный
оператором текст. В Room-таблице `accessKey` нет колонки `lastUsed`, и эндпоинта
истории использования ключей в 9.10.0 не существует.

Поэтому имя определяется сопоставлением кода с текстом события. Это устойчиво к
переформулировкам, но зависит от того, что оператор вообще печатает код в тексте.
Если код не найден, событие приходит без `key_name` — это не ошибка, а штатный
исход. Приватные метки, которые фильтрует приложение, на сервер не отправляются:
`eventTypes` всегда `null`, а выбранные пользователи живут только в UI.
