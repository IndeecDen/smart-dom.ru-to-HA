# История изменений

Формат по [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [Semantic Versioning](https://semver.org/lang/ru/).

## [Не выпущено]

### Добавлено

- Событие `key_activated` на сущностях истории доступа: «дверь открыта
  электронным ключом». Тип `accessKeyActivated` приходил и раньше, но
  отбрасывался — в сопоставлении были только два типа звонка.
- Разбор realtime-пуша `placeEvent` (ключ `u` в FCM). Раньше канал читал только
  `PushType`, то есть вызов домофона; остальные события оператора не доходили.
- Локальные имена ключей в параметрах интеграции: «КОД = Имя», по одному в
  строке. Код сопоставляется поиском в тексте события в любом регистре, поэтому
  переформулировка оператором сообщения не ломает определение.
- Атрибут `key_name` у событий доступа.

### Исправлено

- Сущность `event.<домофон>_history_access` (сводная история по адресу) не
  срабатывала ни разу: `place_id` приходит из API как число, а сравнение шло со
  строкой, поэтому условие не выполнялось никогда. Теперь идентификатор
  нормализуется при создании сущности.

### Безопасность

- Текст события оператора не выходит за пределы `history.py`: наружу отдаётся
  только разрешённое имя. Код ключа не попадает в атрибуты сущностей, запись
  истории и диагностику.
- Одно и то же открытие приходит и пушем, и опросом; события дедуплицируются по
  backend-идентификатору, поэтому уведомление не сработает дважды.

### Ограничено

- Живого события `accessKeyActivated` не наблюдали: тип, ключ пуша и поля
  payload сверены с APK 9.10.0, но фактический текст и тип источника события на
  аккаунте не подтверждены.

## [0.1.0] — 2026-09-28

Первый публичный релиз. Ранее сборка распространялась как `0.1.0-beta.1`.

### Добавлено

- Управление домофоном, калиткой и шлагбаумом через платформу `lock`.
- Камеры: снимок, поток HLS, RTSP-ссылки для go2rtc, управление потоками и
  восстановление после сбоев.
- Архив записей камер через платформу `media_source` и прокси нарезок.
- Входящий звонок домофона: FCM-событие, собственный SIP-стек (диалог, SDP,
  RTP, STUN, Digest), действия `answer` и `hangup`, состояние звонка в сенсоре.
- Собственный SIP-мост без внешнего SIP-сервера и карточка микрофона с
  управлением talk-сессией.
- Lovelace-карточки `custom:mdr-intercom-call-card` и
  `custom:mdr-event-history-card`, локализация ru/en.
- Платформы `sensor` (баланс, срок блокировки, RTSP-ссылки go2rtc, состояние
  звонка), `binary_sensor` (блокировка) и `switch` («Не беспокоить» для
  домофона и управляющей компании).
- События вызова домофона, доступа по ключам, движения и обращений для
  автоматизаций.
- 30+ действий: временные пропуски, электронные ключи, настройки личных камер,
  документы, обращения, финансы, инвентаризация идентификаторов.
- Диагностика с редактированием секретов.
- Тесты контрактов API профиля приложения 9.10.0, перенос регрессии
  исходного проекта, unit-тесты SIP-протокола и карточек на TypeScript.

### Изменено

- Отдельный домен `my_dom_ru` и собственные имена ресурсов, чтобы сборка
  не конфликтовала с `elektronny_gorod`.
- Профиль Android-приложения ЭР-Телеком 9.10.0 (versionCode 91000020).
- Публичные идентификаторы Firebase-проекта приложения используются для
  серверной регистрации устройства в FCM.
- Указатели документации и кодовладельца переведены на репозиторий сборки.

### Безопасность

- Токены доступа, refresh-токены, пароли, коды из SMS, коды ключей и ссылки
  временных пропусков не попадают в логи, атрибуты сущностей и диагностику.
- Небезопасные команды (открытие двери, PTZ, пропуски, ключи) защищены от
  повторного выполнения и отправки без подтверждённой учётной записи.

### Ограничения

- Проверки входа в облако, живого звонка и физического открытия двери на
  реальном адресе не проводились. Уровень подтверждения каждой функции указан в
  [docs/FEATURES.md](docs/FEATURES.md).
- Платёжные операции, привязка камер по Wi-Fi, Bluetooth-поиск, гостевой QR-вход,
  биометрия, зоны движения, тарифы и чат поддержки остаются в официальном
  приложении.
