## [0.1.2] — 2026-10-05

### Исправлено

- Периодическое обновление имён FCM принимает время от таймера HA. Индексы
  загружаются для всех адресов отдельно, сохраняются при сбое API и очищаются
  при успешном пустом ответе.
- Карточка истории и WebSocket-обработчик показывают проходы ключом, включая
  распознанные `infoNotification`, с именем ключа и корректной областью адреса.
- Некорректная дата из истории больше не обрушает отрисовку карточки.
- Отмена жеста открытия не отправляет команду; повторные нажатия во время
  открытия и события другого указателя игнорируются.
- Видеокарточка явно загружает ленивый модуль плеера HA; WebRTC-плеер
  восстанавливается после повторного появления камеры.
- Уточнены ограничения распознавания проходов при изменении текста оператора.
- Исправлен пример карточки вызова в README: обязательный `call_state` вместо
  неподдерживаемого `entity`; добавлены история и инструкция обновления ресурса.

## [0.1.1] — 2026-10-02

### Добавлено

- Фирменная графика интеграции, логотип README и social preview репозитория.
- Событие `key_activated` для истории доступа с именем ключа из облака:
  FCM-пуш даёт быстрое уведомление, опрос истории восполняет пропущенное.
- Диагностика событий по ключам без раскрытия кода и исходного текста.

### Исправлено

- Архивы релиза теперь включают графику из `brand/`.
- Регистрация FCM использует идентификатор сборки ЭР-Телеком (`appId=4`), что
  позволило получать `placeEvent` и вызовы на проверенном аккаунте.
- События открытия ключом распознаются по содержимому `infoNotification`, а
  не только по типу `accessKeyActivated`, который не встретился в живой истории.
- Числовые идентификаторы адреса и домофона нормализуются перед сопоставлением:
  сводная сущность и сущность единственного домофона получают событие.
- Имена ключей берутся из облака; временная настройка ручных имён удалена.
- Примеры автоматизаций в README реагируют на повторные события одного типа.
- README и документация приведены в соответствие с кодом, включая камеры
  соседних подъездов и фактический объём проверки на живом аккаунте.

### Безопасность

- Код ключа и полный текст оператора не выводятся в атрибуты и диагностику;
  журнал содержит только ограниченный диагностический образец без секретов.
- Одно и то же открытие приходит и пушем, и опросом; события дедуплицируются по
  backend-идентификатору, поэтому уведомление не сработает дважды.

### Ограничения

- На живом аккаунте подтверждены FCM и распознавание прохода ключом. Потоки и
  команды на всех моделях и тарифах этим не подтверждаются.

## [0.1.0] — 2026-09-28

Первый публичный релиз. Ранее сборка распространялась как `0.1.0-beta.1`.

### Добавлено

- Управление домофоном, калиткой и шлагбаумом через платформу `lock`.
- Камеры: снимок, поток HLS, RTSP-ссылки для go2rtc, управление потоками и
  восстановление после сбоев.
- Архив записей камер через платформу `media_source` и прокси нарезок.
- Входящий звонок домофона: FCM-событие, собственный SIP-стек (диалог, SDP,
  RTP, STUN, Digest), действия `answer` и `hangup`, состояние звонка в сенсоре.
- Собственный SIP-мост без внешнего SIP-сервера и карточка микрофона с
  управлением talk-сессией.
- Lovelace-карточки `custom:mdr-intercom-call-card` и
  `custom:mdr-event-history-card`, локализация ru/en.
- Платформы `sensor` (баланс, срок блокировки, RTSP-ссылки go2rtc, состояние
  звонка), `binary_sensor` (блокировка) и `switch` («Не беспокоить» для
  домофона и управляющей компании).
- События вызова домофона, доступа по ключам, движения и обращений для
  автоматизаций.
- 30+ действий: временные пропуски, электронные ключи, настройки личных камер,
  документы, обращения, финансы, инвентаризация идентификаторов.
- Диагностика с редактированием секретов.
- Тесты контрактов API профиля приложения 9.10.0, перенос регрессии
  исходного проекта, unit-тесты SIP-протокола и карточек на TypeScript.

### Изменено

- Отдельный домен `my_dom_ru` и собственные имена ресурсов, чтобы сборка
  не конфликтовала с `elektronny_gorod`.
- Профиль Android-приложения ЭР-Телеком 9.10.0 (versionCode 91000020).
- Публичные идентификаторы Firebase-проекта приложения используются для
  серверной регистрации устройства в FCM.
- Указатели документации и кодовладельца переведены на репозиторий сборки.

### Безопасность

- Токены доступа, refresh-токены, пароли, коды из SMS, коды ключей и ссылки
  временных пропусков не попадают в логи, атрибуты сущностей и диагностику.
- Небезопасные команды (открытие двери, PTZ, пропуски, ключи) защищены от
  повторного выполнения и отправки без подтверждённой учётной записи.

### Ограничения

- Проверки входа в облако, живого звонка и физического открытия двери на
  реальном адресе не проводились. Уровень подтверждения каждой функции указан в
  [docs/FEATURES.md](docs/FEATURES.md).
- Платёжные операции, привязка камер по Wi-Fi, Bluetooth-поиск, гостевой QR-вход,
  биометрия, зоны движения, тарифы и чат поддержки остаются в официальном
  приложении.
